# מעבר עתידי ל־Netlify

## מה מוכן

- `netlify.toml`: פקודת בנייה `pnpm run build:netlify`, תיקיית פרסום `dist-netlify`, Node 22.
- `scripts/build-netlify.mjs`: מפיק HTML מוקדם של שנארה ואז מחבר React לדף; מעתיק את נירוונה והמסלולים לנתיבים שלהם.
- `netlify/entry-client.tsx`, `entry-server.tsx`: משתמשים ישירות ב־`app/page.tsx`; כל שינוי בעמוד ובתוכן משותף גם לבניית Netlify.
- התמונות, הלוגואים וספריות האנימציה המקומיות מועתקים מ־`public/`.
- שלושת הנתיבים הם קובצי HTML עצמאיים. אין צורך ב־SPA fallback, בשרת Cloudflare או בבסיס נתונים עבור האתר הציבורי הנוכחי.

## פריסה בעתיד

1. ב־Netlify לבחור Import an existing project ולחבר את `avivbyby/SHANARA-NIRVANA`.
2. לבחור ענף `main`. להשאיר Base directory ריק.
3. ההגדרות ייקראו מ־`netlify.toml`.
4. לאחר הבנייה לבדוק `/`, `/nirvana`, `/nirvana/plans`, פתיחת אלבומים, גלריה, תפריט במובייל וטופס המסלולים.
5. לחבר דומיין רק לאחר בדיקת הפריסה.

אפשר גם להריץ את הבנייה מקומית ולהעלות את תוכן `dist-netlify` ידנית. אין להעלות את תיקיית קוד המקור במקום תוצרי הבנייה.

לא נוצר כאן אתר Netlify, לא חובר דומיין ולא שונו ההרשאות של האתר הפעיל.

## שמירת עדכונים

יש לערוך את קובצי המקור, להפיק מחדש את הבנייה ולהעלות commit חדש. אין לערוך קבצים בתוך `dist-netlify` או את חבילות ה־JavaScript שנוצרו. התיקייה אינה נשמרת ב־Git כי ניתן לשחזר אותה מהקוד ומה־lockfile.

קובצי `worker/`, `.openai/hosting.json` ו־`vite.config.ts` שייכים לבנייה המקורית של Sites. אין צורך לשנות אותם עבור Netlify. אם מוסיפים בעתיד התחברות, API או בסיס נתונים, יש להתאים את החלקים האלה בנפרד; הם אינם חלק מהאתר הסטטי הנוכחי.

מקור ההגדרות: [Netlify file-based configuration](https://docs.netlify.com/build/configure-builds/file-based-configuration/).
